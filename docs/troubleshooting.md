# 트러블슈팅

개발·운영 중 실제로 겪은 문제와 해결 과정입니다.

---

## 1. 실기기에서만 앱이 즉시 종료되는 문제

**증상**
에뮬레이터에서는 정상인데, 빌드한 APK를 실제 폰에 설치하면 실행 1초 안에 튕겼습니다.

**원인 추적**
에뮬레이터는 멀쩡하고 기기만 죽는다는 점에서 네이티브 영역 문제로 좁혔습니다.
Android Studio Logcat에서 `FATAL EXCEPTION` 로그를 확인했습니다.

```
java.lang.NoSuchMethodError: ... getDirectConverter ... at FontLoaderModule
```

`expo-doctor`로 점검한 결과 **expo-font가 두 버전(57.0.1 / 14.0.12) 동시에 설치**되어 네이티브 빌드가 충돌하고 있었습니다.

**해결**
```bash
npx expo install --fix     # Expo 패키지 버전 정렬
# node_modules + lock 파일 재설치로 중복 제거
npx expo-doctor             # 통과 확인
```

**배운 점**
JS 레벨에서 재현되지 않는 크래시는 네이티브 로그를 봐야 원인이 보입니다.
`expo-doctor`로 패키지 버전 정합성을 먼저 확인하는 습관이 생겼습니다.

## 2. 지도에 카페가 일부만 표시되던 문제

**증상**
지도를 넓게 보면 분명히 등록된 카페인데 마커가 보이지 않는 경우가 있었습니다.

**원인**
초기 구현에서 지도 데이터를 가져올 때 **상위 50개로 잘라서** 요청하고 있었습니다.
카페가 적을 때는 문제가 드러나지 않다가, 데이터가 쌓이면서 노출되었습니다.

**해결**
지도 조회는 개수 제한을 제거하고 전체를 불러오되,
**supercluster로 클러스터링**해 렌더링 비용을 일정하게 유지했습니다.
줌 레벨에 따라 가까운 마커를 묶어 표시하므로 마커 수가 늘어도 프레임 저하가 없습니다.

**배운 점**
"일단 잘라서 가져오기"는 초기에는 편하지만 데이터가 늘면 기능 결함이 됩니다.
제한을 둘 거라면 화면에 보이는 영역 기준이어야 했습니다.

## 3. 지도 라이브러리 교체 (구글 지도 → 네이버 지도)

**문제**
국내 환경에서 상호·건물 정보의 정확도와 한글 표기가 아쉬웠고, 지도 조작 시 성능도 만족스럽지 않았습니다.

**해결**
네이버 지도 SDK로 이관했습니다. 교체하면서 클러스터링 로직도 다시 붙였고,
마커 메모이제이션을 적용해 지도 이동 시 불필요한 리렌더를 줄였습니다.

**부수 작업**
교체 후 사용하지 않게 된 구글 지도 API 키와 의존성을 제거했습니다.
APK에 포함되어 배포되는 키를 하나라도 줄이는 편이 안전하다고 판단했습니다.

## 4. 글·리뷰를 수정하면 첨부 사진이 사라지던 문제

**증상**
사진이 있는 글을 수정하면 본문은 유지되는데 사진이 전부 사라졌습니다.

**원인**
수정 API가 `imageKeys`를 보내지 않아 서버가 "이미지 없음"으로 해석하고 `replaceImages(null)`을 실행해 전부 삭제하고 있었습니다.
수정 화면이 **기존 이미지의 key를 모르는 것**이 근본 원인이었습니다.

**해결**
- 상세 응답에 `imageKeys`를 추가해 수정 화면이 기존 이미지를 식별할 수 있게 했습니다.
- `imageUrls`와 `imageKeys`를 같은 순서로 내려, 같은 인덱스끼리 짝이 되도록 했습니다.
- 수정 화면은 기존 사진은 key를 유지하고, **새로 추가한 사진만 업로드**한 뒤 최종 목록을 전송합니다.

## 5. 조회수가 새로고침마다 올라가던 문제

**증상**
같은 사용자가 글을 여러 번 열면 조회수가 계속 증가했습니다.

**해결**
조회 이력 테이블(`feed_view`)을 만들고 `(글, 사용자, 날짜)`에 유니크 제약을 걸어
**하루 1회만** 집계하도록 했습니다. 본인 글은 집계에서 제외하고, 자정이 지나면 다시 카운트됩니다.

**배운 점**
중복 방지는 애플리케이션 조건문보다 **DB 제약으로 보장**하는 편이 안전합니다.
동시 요청이 들어와도 중복이 생기지 않습니다.

## 6. 등록 후 뒤로 가면 작성 화면이 다시 뜨던 문제

**증상**
리뷰나 글을 등록한 뒤 뒤로 가기를 누르면 방금 작성한 화면이 다시 나타났고,
거기서 등록을 한 번 더 누르면 "이미 작성했습니다" 오류가 나거나 **같은 글이 중복 등록**되었습니다.

**원인**
React Navigation v6까지는 `navigate('Main')`이 스택에 있는 기존 화면으로 **되돌아갔지만**,
v7부터는 **새 화면을 push**하도록 동작이 바뀌었습니다. 그래서 작성 화면이 스택에 남아 있었습니다.

```
[홈] → [카페 상세] → [리뷰 작성] → [홈(새로 push)]
                        ↑ 뒤로 가기 시 여기로 돌아옴
```

**해결**
`popTo`로 교체해 작성 화면을 스택에서 제거했습니다.
카페 상세에서 진입한 경우에는 `goBack()`으로 상세 화면에 복귀해, 방금 쓴 리뷰가 바로 보이도록 했습니다.

**배운 점**
메이저 버전 업그레이드 시 **동작이 바뀐 API**는 타입 오류를 내지 않아 발견이 늦습니다.
증상만 보면 UI 버그 같지만 원인은 라이브러리 동작 변경이었습니다.

## 7. 인증 메일이 스팸으로 분류되던 문제 (Gmail SMTP → AWS SES)

**문제**
개인 Gmail SMTP로 인증코드를 발송하다 보니 스팸 분류 위험이 있고, 발송 한도와 보낸 사람 주소도 서비스에 맞지 않았습니다.

**해결**
AWS SES로 전환했습니다.
- `crccafe.com` 도메인을 Easy DKIM으로 인증 (DNS에 CNAME 3건 등록)
- 샌드박스 해제(프로덕션 액세스) 신청 및 승인
- 발신 주소를 `noreply@crccafe.com`으로 변경

**설계상 걸림돌**
기존 코드는 보내는 사람 주소를 `spring.mail.username`에서 가져왔는데,
SES는 **SMTP username이 이메일이 아니라 자격증명 문자열**입니다.
그래서 FROM 주소를 별도 환경변수로 분리하고, 값이 없으면 기존 방식으로 동작하도록 기본값을 두어
**배포만으로는 동작이 바뀌지 않게** 했습니다. 환경변수 교체 시점에만 전환되도록 한 것입니다.

```java
@Value("${MAIL_FROM:${spring.mail.username}}")
private String from;
```

**결과**
도메인 기반 발신으로 바뀌면서 받은편지함에 정상 도착하고, 발송 한도도 하루 5만 건으로 확보했습니다.

## 8. 이메일 별칭으로 계정을 무제한 생성할 수 있던 문제

**증상**
`user+1@gmail.com`, `user+2@gmail.com`, `u.ser@gmail.com`은 모두 같은 메일함으로 들어오지만
서비스에서는 서로 다른 계정으로 가입되었습니다. 한 사람이 계정을 계속 만들 수 있는 상태였습니다.

**해결**
중복 판정 전용 **대표 주소(canonical)** 컬럼을 추가했습니다.
- 로컬파트의 `+` 뒤를 제거
- gmail/googlemail은 점(`.`)도 제거하고 도메인을 통일
- 가입 요청·인증 완료·중복 확인 세 지점 모두 대표 주소로 비교

로그인과 메일 발송은 사용자가 입력한 **원래 주소를 그대로** 사용합니다.

**운영 중 마이그레이션 고려**
이미 별칭으로 만들어진 계정이 존재했기 때문에 유니크 제약은 걸지 않았습니다.
제약을 걸면 기존 데이터와 충돌해 애플리케이션이 기동하지 않기 때문입니다.
**기존 계정은 그대로 두고 신규 가입만 차단**하는 방식으로 적용했습니다.

## 9. 스토어 업로드 키 불일치

**증상**
EAS로 앱을 빌드하려 하자 "새 키스토어를 만들까요?"라는 질문이 나왔고,
그대로 진행하면 Google Play가 업로드를 거부했습니다.

**원인**
Play Console에 등록된 업로드 키가 **로컬 키스토어**였는데,
EAS 서버에는 해당 키가 없어 매번 새 키를 생성하려 했던 것입니다.

**확인 방법**
세 값을 모두 대조해 원인을 특정했습니다.
```bash
keytool -list -v -keystore upload.keystore -alias <alias>   # 로컬 키
keytool -printcert -jarfile app.aab                          # 기존 배포본 서명
# Play Console > 앱 서명 > 업로드 키 인증서 SHA-1
```

**해결**
`eas.json`의 production 프로필에 `android.credentialsSource: "local"`을 지정해
로컬 키스토어로 서명하도록 고정했습니다. iOS는 기존 원격 자격증명을 유지했습니다.

**배운 점**
서명 키는 한 번 어긋나면 되돌리기 어렵습니다.
설정을 저장소에 명시해 두어 다음 빌드에서 같은 실수를 반복하지 않도록 했습니다.

## 10. 운영 환경 설정 누락으로 서버가 기동하지 않던 문제

**증상**
배포 후 백엔드 컨테이너가 재시작을 반복했습니다.

**원인**
`SecurityConfig`와 `WebSocketConfig`가 `app.cors.allowed-origins`를 필수로 읽는데
설정 파일에 해당 항목이 없어 애플리케이션 컨텍스트 로딩에 실패했습니다.

**해결**
설정을 추가하고, **예시 파일(`application.yaml.example`, `.env.example`)에 필수 항목을 모두 반영**했습니다.
예시 파일만 보고 세팅해도 서버가 뜨도록 맞춘 것입니다.

**배운 점**
설정 누락은 코드 리뷰에서 걸러지지 않습니다.
예시 파일을 실제 필수 항목과 동기화해 두는 것이 팀 작업에서 특히 중요했습니다.
